# Подключение API MAX (мессенджер) к max-clinic-app

Инструкция составлена по официальной документации: https://dev.max.ru/docs

---

## 1. Что за файлы лежат в корне проекта

| Файл | Назначение |
|---|---|
| `cloudflared.exe` | Клиент Cloudflare Tunnel. Позволяет открыть локальный сервер наружу по HTTPS. **⚠️ Если не работает — см. раздел 9 с альтернативами.** |
| `start_public.bat` | Скрипт запуска: поднимает локальный dev-сервер и пробрасывает его через Cloudflare Tunnel. |
| `start-dev.bat` | Обычный локальный запуск без публичного доступа. |

---

## 2. Важное из документации MAX

1. **Мини-приложения работают только внутри MAX** и не могут существовать автономно.
2. Приложение должно быть доступно **только по HTTPS**.
3. Мини-приложение привязывается к **боту** — без бота кнопка запуска не появится.
4. Для доступа к данным пользователя и API MAX внутри приложения нужно подключить **библиотеку MAX Bridge** (объект `window.WebApp`).

---

## 3. Куда вставлять API-ключ (токен) мессенджера

API-ключ (токен бота) **не вставляется в код**. В этом проекте он задаётся через переменные окружения.

### Шаг 1. Создайте файл `.env` в корне проекта

Рядом с `.env.example` создайте файл `.env` (если его ещё нет) и добавьте:

```env
# Токен API бота MAX (выдаётся при создании бота на business.max.ru)
VITE_MAX_BOT_TOKEN=ваш_токен_сюда

# Базовый URL API MAX (см. документацию dev.max.ru/docs-api)
VITE_MAX_API_URL=https://api.max.ru
```

> ⚠️ Файл `.env` уже добавлен в `.gitignore` — токен не попадёт в git.
> ⚠️ **Никогда не вставляйте реальный токен в файлы документации / README / код.** Если токен уже куда-то попал (например, в этот файл или в git-историю) — пересоздайте бота или отзовите токен на https://business.max.ru/self и получите новый.

### Шаг 2. Где токен взять

1. Откройте **платформу MAX для партнёров**: https://business.max.ru/self
2. Зарегистрируйте профиль организации / ИП / самозанятого (нужно устройство с приложением MAX).
3. Раздел **Чат-боты → Перейти → Создать бота**.
4. После создания бота в его настройках будет **токен API** — скопируйте его.
5. Вставьте токен в `.env` вместо `ваш_токен_сюда`.

### Шаг 3. Как токен используется в коде

В коде его читают так (примеры для этого проекта):

```ts
const token = import.meta.env.VITE_MAX_BOT_TOKEN;
const apiUrl = import.meta.env.VITE_MAX_API_URL;
```

Запросы к API MAX идут в сервисах проекта: `src/api/*/service.ts`.

## 4. Как подключить сайт как мини-приложение в MAX

1. Запустите публичный доступ (см. раздел 9 — выберите способ, который работает).
2. Откройте https://business.max.ru/self → **Чат-боты → Перейти**.
3. Выберите нужного бота (если их несколько).
4. **Расширенные настройки → Настроить**.
5. Вставьте **URL мини-приложения** (публичную HTTPS-ссылку) в поле для ссылки.

   Требования к URL:
   - Только `https://`
   - Без пробелов; допустимы латиница, цифры, точка, дефис
   - Длина до 1024 символов

6. Выберите вид кнопки запуска: **Открыть / Старт / Играть / без названия** → **Сохранить**.
7. Готово — в чате с ботом появится кнопка запуска мини-приложения.

## 5. Ссылки для запуска (диплинки)

Формат:

```
https://max.ru/<botName>?startapp=<payload>
```

Примеры:

```
https://max.ru/MyClinicBot?startapp
https://max.ru/MyClinicBot?startapp=promo
```

Внутри приложения параметры доступны через MAX Bridge:
- `window.WebApp.initDataUnsafe.start_param` — стартовые параметры
- `window.WebApp.initData` — строка со всеми стартовыми параметрами

> Payload: только латиница, цифры, `_` и `-`, до 512 символов.

---

## 6. Подключение библиотеки MAX Bridge (обязательно для доступа к API)

Без неё приложение не получит данные пользователя (`initData`, `initDataUnsafe`) и не сможет вызывать методы MAX.

Установка:

```bash
npm i @vkontakte/max-bridge
```

(точное имя пакета и способ подключения смотрите в разделе «MAX Bridge»: https://dev.max.ru/docs/webapps/bridge)

Основное использование:

```ts
import { WebApp } from '@vkontakte/max-bridge';

// Данные пользователя и стартовые параметры
const initData = WebApp.initData;
const startParam = WebApp.initDataUnsafe.start_param;
```

## 7. Деплой на Vercel (рекомендуемый способ)

**Почему это лучше туннелей:**
- ❌ Туннели (Cloudflare, ngrok) дают временный адрес, который меняется при каждом запуске
- ✅ Vercel даёт **постоянный** HTTPS-адрес — вставили один раз в настройки бота и забыли
- ✅ Бесплатный хостинг для статики / Vite-проектов
- ✅ Автоматический деплой при пуше в git

### Установка Vercel CLI

```bash
npm i -g vercel
```

### Деплой одной командой

```bash
vercel --prod
```

Вас попросят:
1. Войти в аккаунт Vercel (можно через GitHub)
2. Подтвердить настройки (обычно всё подхватывается автоматом из `vite.config.ts`)

После деплоя вы получите адрес вида:
```
https://max-clinic-app.vercel.app
```

Этот адрес **постоянный** — вставьте его в настройки бота MAX (п. 4).

### Автоматический деплой при пуше в git

1. Запушьте проект на GitHub.
2. Зайдите на https://vercel.com → **Add New → Project**.
3. Импортируйте репозиторий.
4. Vercel сам определит, что это Vite-проект, и настроит сборку.
5. При каждом пуше в `main/master` будет происходить автоматический деплой.

## 8. Альтернативные способы (туннели)

Если Vercel по каким-то причинам не подходит, вот 4 рабочих способа получить HTTPS-ссылку на локальный сервер.

### Способ A. ngrok (рекомендуемый среди туннелей)

**Плюсы:** стабильный, бесплатный статический домен после регистрации, простая команда.

**Установка:**
```bash
npm i -g ngrok
```

**Запуск:**
```bash
ngrok http 5173
```

После запуска появится ссылка вида:
```
https://abc123.ngrok-free.app
```

**Чтобы получить постоянный адрес (бесплатно):**
1. Зарегистрируйтесь на https://ngrok.com
2. Скопируйте **Auth Token** из личного кабинета
3. Привяжите токен: `ngrok config add-authtoken ваш_токен`
4. Запустите с фиксированным субдоменом: `ngrok http 5173 --domain=мой-субдомен.ngrok-free.app`
5. Теперь адрес не меняется при перезапуске.

### Способ B. localhost.run (SSH-туннель, без установки)

**Плюсы:** не нужно ничего ставить — работает через встроенный SSH.

**Запуск:**
```bash
ssh -R 80:localhost:5173 localhost.run
```

Вы получите ссылку вида:
```
https://случайное-имя.localhost.run
```

**Минус:** адрес меняется при каждом запуске.

### Способ C. localtunnel (npm, без регистрации)

**Плюсы:** не требует регистрации, одна команда.

**Запуск:**
```bash
npx localtunnel --port 5173
```

Вы получите ссылку вида:
```
https://случайное-имя.loca.lt
```

**Минусы:** адрес меняется, иногда требует подтверждения по IP.

### Способ D. Cloudflare Tunnel (из коробки, если работает)

У вас уже есть `cloudflared.exe` и `start_public.bat`. Просто запустите:

```
start_public.bat
```

Скрипт выдаст ссылку вида `https://<случайное>.trycloudflare.com`.

**Если не работает — возможные причины:**
- Блокировка Cloudflare вашим провайдером (попробуйте через VPN)
- Файрвол / антивирус блокирует `cloudflared.exe`
- Требуется обновить `cloudflared.exe` (скачайте свежую версию с https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/downloads/)

## 9. Сравнение способов

| Способ | Адрес | Нужна регистрация | Нужно ставить | Рекомендую |
|---|---|---|---|---|
| **Vercel** (деплой) | ✅ Постоянный | Да | `vercel` CLI | ✅ **Лучший вариант** |
| ngrok | Можно сделать постоянным | Да | `ngrok` CLI | ✅ Если нужен туннель |
| localhost.run | Меняется каждый раз | Нет | Только SSH | Временное тестирование |
| localtunnel | Меняется каждый раз | Нет | `npx` | Быстрый тест |
| Cloudflare Tunnel | Меняется каждый раз | Нет | `cloudflared.exe` | Если работает |
