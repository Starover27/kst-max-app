# План реализации MAX Clinic App

Цель: привести проект к состоянию стабильного эталонного MAX Mini App по `docs/design-reference.png`.
Принципы: сначала зелёная сборка, потом единый дизайн, потом сценарии, потом интеграции.

---

## Этап 0. Стабилизация сборки и уборка (критично, без него дальше не двигаться)

Задачи:
1. Удалить или починить мёртвый код:
   - `src/features/booking/steps/*` (7 файлов) — не подключены к роутеру и ожидают несуществующий `useBookingStore`. Решение: удалить папку `steps` (мастер будет построен заново на этапе 3 поверх единого store).
   - `src/features/home/*` — дублирует `pages/home/HomePage`, не используется роутером. Решение: удалить после переноса удачных компонентов (Header/Greeting/HeroImage/QuickActions/PromoCard), если они лучше текущих, либо удалить целиком.
   - `max-clinic-app/` (пустой дубликат), `kst27_home.html`, `kst27_doctors.html`, `kst27_price.html`, `tmp_home.html` — прототипы, убрать из корня (в `docs/` или удалить).
2. Починить оставшиеся ошибки TS:
   - `src/app/router.tsx`: `import AnalysisPage from ...`, `import ProfilePage from ...` (default-экспорт).
   - `src/pages/analysis/AnalysisPage.tsx`: добавить `import Page from '../../shared/ui/Page'`, убрать неиспользуемый `useState`.
   - `src/api/booking/mock.ts`: убрать неиспользуемый параметр `payload`.
3. Подключить `src/app.css` в `src/main.tsx` (`import './app.css'`) — сейчас вся визуальная система экранов не применяется.
4. Lint: заменить `any` на типизированные ответы (`unknown` + мапперы) в `src/api/**`, `src/shared/api/client.ts`, `src/pages/LoginPage.tsx`, admin-страницах. Цель: `npm run lint` без ошибок.
5. Фикс `.env.example`/`api.ts`: `BASE_URL` читать из `import.meta.env.VITE_API_BASE_URL`.

Критерий готовности: `npm run build` и `npm run lint` проходят без ошибок.

## Этап 1. Дизайн-система и каркас UI

Задачи:
1. Единый источник токенов: устранить дублирование между `src/app.css` (:root --red #c8102e) и `src/shared/styles/colors.css` (--red #E3232A). Утвердить один набор:
   - `--red: #E3232A`, `--red-dark`, `--red-light`
   - `--orange: #F97316` (активная дата, действие «перенести»)
   - `--green: #16A34A` (статусы «готово»)
   - `--gray`/`--gray-dark`/`--gray-light`
   - градиенты `--gradient-primary: linear-gradient(100deg, var(--red) 0%, #7A1220 55%, #4B5563 100%)` и `--gradient-accent-orange: linear-gradient(100deg, var(--orange) 0%, #B3261E 60%, #57534E 100%)`.
2. Разнести глобальные классы `app.css` по CSS Modules компонентов (или оставить единым подключённым слоем — решение на старте этапа). Единый подход: CSS Modules для компонентов, токены — глобально.
3. Расширить токены: z-index (`--z-nav: 40`, `--z-modal: 60`, `--z-toast: 70`), safe-area, состояния (`:active`, `:disabled`).
4. Унифицировать `shared/ui`: Button (primary/ghost), Chip, Card, SearchInput, DoctorCard, BottomNavigation, Modal, Page, Section, Toggle, EmptyState. Страницы должны использовать эти компоненты вместо inline-стилей.
5. Типографика: Inter (уже в стеке), шкала 11/13/15/17/20/24px, веса 500/600/700/800.

Критерий: все текущие 4 рабочих экрана выглядят идентично эталону (пиксель-ревью по скриншоту).

## Этап 2. Главный экран и навигация по эталону

Задачи:
1. `HomePage`: логотип из `assets/logo.png`, приветствие с именем пользователя (из store/MAX), фото клиники (`assets/clinic.jpg` или `hero.png` — выбрать одно), 8 быстрых действий, карточка преимущества.
2. `AppShell` / `BottomNavigation`: 4 вкладки (Главная, Врачи, Запись, Профиль), активная — красная с заливкой, safe-area-bottom.
3. Подключить имя пользователя и тему: `initMaxBridge()` в `main.tsx`, `getMaxUser()` → `appStore.setUser`, `getMaxTheme()` → класс на `<html>`.
4. Роуты быстрых действий: «Мои записи» → `/appointment`, «Анализы» → `/analysis`, «Оплата» → `/profile#payments` (или заглушка), «Врачи» → `/doctors`, «Отзывы»/«Как добраться» → `openExternalLink` (MAX bridge) или модал.

Критерий: главный экран 1:1 со скриншотом; навигация работает на всех экранах.

## Этап 3. Полный сценарий записи (воронка)

Задачи:
1. Единый booking-store (zustand) с шагами: врач → услуга → дата → время → данные пациента → подтверждение → успех.
2. `BookingPage` переписать как пошаговый мастер:
   - `DoctorStep`: выбор врача (список/поиск/фильтры, переиспользует DoctorsPage-логику).
   - `ServiceStep`: выбор услуги (нужен источник данных — `src/entities/Service.ts` уже есть; данные из `shared/data` или API).
   - `DateStep`: горизонтальный календарь на 14 дней, активная дата — оранжевая.
   - `TimeStep`: сетка 3 колонки, занятые слоты disabled.
   - `PatientStep`: форма (ФИО, телефон) на react-hook-form + zod.
   - `ConfirmStep`: сводка + CTA «Подтвердить запись».
   - `SuccessStep`: экран успеха, переход в «Мои записи».
3. История записей: `bookingStore` хранит массив записей (localStorage), не одну.
4. Роут `/booking/:doctorId` — старт мастера с предвыбранным врачом.

Критерий: полный сценарий от выбора врача до подтверждённой записи в истории.

## Этап 4. Экраны «Мои записи», «Анализы», «Профиль» по эталону

«Мои записи» (`AppointmentsPage`):
- Градиентный hero с датой/месяцем, список записей, детали («О приёме», кабинет), действия: перенести (оранжевый), отменить (красный), тумблер напоминания.

«Анализы» (`AnalysisPage`):
- Chips-фильтры: Все / Готовые / В работе.
- Карточка анализа: название, дата, статус, кнопка «Смотреть результат» (модаль/страница) и «Скачать PDF» (заглушка → API).

«Профиль» (`ProfilePage`):
- Градиентная шапка, аватар (пользователь, не клиника), имя, телефон, кнопка редактирования.
- Меню: Личные данные, Мои записи, Анализы, Оплата, Уведомления (тумблер), Поддержка, О клинике. Кнопка «Выйти».
- Редактирование профиля — форма в модале (react-hook-form + zod).

Критерий: все 6 экранов эталона реализованы и соответствуют скриншоту.

## Этап 5. API-контур и данные

Задачи:
1. `shared/api/client.ts`: Authorization Bearer из `appStore`, обработка 401 → refresh/логин, типизация без `any`.
2. Решить источник данных для MVP:
   - Вариант A (без бэкенда): вернуть моки (`VITE_USE_MOCK=true`), данные врачей/анализов/записей из `shared/data`.
   - Вариант B (с бэкендом): реализовать backend (адрес, CORS) и подключить реальные сервисы.
3. React Query: использовать для `fetchDoctors`, `fetchAnalyses`, `fetchAppointments` (заменить ручные useState-загрузки на страницах).
4. Типизация DTO: убрать `any` в мапперах.

Критерий: все страницы получают данные через единый контур (mock или real), без хардкода в JSX.

## Этап 6. MAX Mini App интеграция

Задачи:
1. `index.html`: подключить MAX SDK-скрипт, `lang="ru"`, title клиники, meta viewport с `viewport-fit=cover`.
2. `main.tsx`: `initMaxBridge()` до рендера; если bridge доступен — `getMaxUser()` → автологин (без LoginPage), `getMaxTheme()` → CSS-переменные.
3. Заменить noop-адаптер на реальный при наличии SDK (`setAdapter`).
4. BackButton MAX: навигация назад по стеку роутера.
5. `LoginPage` и `auth` — решить: в MAX-контексте авторизация через bridge (пользователь уже есть), логин нужен только для внешнего браузера/админки.

Критерий: приложение корректно стартует внутри MAX WebView (пользователь, тема, back), и в обычном браузере (фолбэки).

## Этап 7. Качество и production

Задачи:
1. Тесты: unit (vitest) на мапперы и stores; e2e (playwright) на сценарий записи.
2. CI: `lint → build → test` (GitHub Actions или аналог).
3. Оптимизация: сжатие фото врачей (webp, <100KB), lazy-load изображений, code-splitting роутов (`React.lazy`).
4. Safe-area (iOS), тёмная тема от MAX, skeleton-загрузки, error-boundaries.
5. Публикация: HTTPS-домен, регистрация Mini App в кабинете MAX (URL, обложка, права), мониторинг ошибок.

## Порядок этапов и зависимости

```
Этап 0 (сборка) → Этап 1 (дизайн-система) → Этап 2 (главный экран)
     ↓
Этап 3 (воронка записи) → Этап 4 (остальные экраны)
     ↓
Этап 5 (API/данные) → Этап 6 (MAX интеграция) → Этап 7 (production)
```

## Риски

- Два контура записи: на этапе 3 обязательно удалить старый `features/booking/steps`, не развивать параллельно.
- Отсутствие бэкенда: этап 5 фиксирует источник данных до начала работы с API.
- Свежие мажорные версии (Vite 8, TS 6, React 19): при проблемах совместимости плагинов допустим даунгрейд Vite до 7.
- Три варианта фото клиники: выбрать один до этапа 2.
